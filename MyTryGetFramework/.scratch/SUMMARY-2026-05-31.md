# TryGet 框架分析总结 - 2026/05/31

## 🎯 核心结论

### ✅ 好消息
1. **V2.2 FrameLoop 已提前实现** - ModuleHost 已支持 5 阶段 Update（EarlyUpdate/FixedUpdate/Update/LateUpdate/EndOfFrame）
2. **代码质量优秀** - ModuleHost 拓扑排序、错误回滚、生命周期管理设计合理
3. **架构清晰** - 纯客户端定位明确，Core 保持纯 C#（不引用 UnityEngine）

### ⚠️ 需要改进
1. **TGTaskScheduler 未感知 Phase** - 只在 Update 阶段运行，无法按 Phase 调度异步操作
2. **EventBus 有 GC 压力** - Dictionary<Type, object> 装箱问题
3. **缺失 Scope 管理** - 无法按场景/玩法卸载部分服务（但需等 Unity 层明确）

### 2. 修复 EventBus.GetEventTypes() GC
**文件**：`Assets/MyTryGetFramework/Runtime/Core/Event/EventBus.cs:60-63`  
**问题**：每次调用都分配新 List  
**修复**：
```csharp
// 当前（❌）
public IReadOnlyList<Type> GetEventTypes()
{
    return new List<Type>(_handlers.Keys);  // 每次分配
}

// 修复（✅）
public IReadOnlyList<Type> GetEventTypes()
{
    return _handlers.Keys.ToArray();  // 一次分配
}
```

**工作量**：10 分钟  
**风险**：极低

**目标**：支持在指定 FramePhase 恢复异步操作

**API 设计**：
```csharp
// 新增 API
await scheduler.Yield(FramePhase.LateUpdate);  // 在 LateUpdate 后恢复

// 实现方式
public sealed class TGTaskScheduler : 
    IEarlyUpdateModule, IFixedUpdateModule, IUpdateModule, 
    ILateUpdateModule, IEndOfFrameModule

    private Dictionary<FramePhase, List<TGTaskCompletionSource>> _yieldQueues;
```

### P1-B：EventBus 零 GC 基准测试
**目标**：量化 GC 压力，决定是否重构

**测试场景**：
- 每帧 Publish 100 次高频事件
