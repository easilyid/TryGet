## 4. V2.1-V2.8 优先级路线图

### 4.1 V2.3 UI 框架（P0，下一里程碑）

**目标**：提供完整 UI 管理能力，让框架可用于真实游戏项目。

**核心能力**：
- IUIModule：窗口注册 / Open / Close / 栈管理 / 层级管理
- UIWindow 生命周期：OnCreate / OnShow / OnHide / OnClose / OnDestroy / OnUpdate
- UIWidget：可复用 UI 组件（按钮/列表/输入框/滚动视图）
- 层级管理：Background / Normal / Fixed / Popup / System / Guide（对标 TEngine）
- 深度排序：sortingOrder 管理 + 子 Canvas 递增
- 可见性控制：layer 切换（WINDOW_SHOW_LAYER / WINDOW_HIDE_LAYER）
- 资源绑定：异步加载 Prefab + IUIResourceLoader 抽象（YooAsset/Addressables/Resources）
- 事件系统集成：UI 事件通过 EventModule 派发

**参考设计分析**（基于 TEngine UIWindow）：
1. **UIWindow 属性**：
   - `WindowName`：窗口唯一标识
   - `WindowLayer`：层级（int，对应 Background=0/Normal=1000/Popup=2000 等）
   - `AssetName`：资源定位地址
   - `FullScreen`：是否全屏窗口（影响下层窗口可见性）
   - `Depth`：sortingOrder（动态调整，子 Canvas 递增）
   - `Visible`：通过 layer 切换实现（显示层 vs 隐藏层，避免频繁 SetActive）

2. **UIWindow 生命周期**（TEngine UIBase）：
   - `OnCreate()`：首次创建时调用（绑定组件、注册事件）
   - `OnShow()`：窗口显示时调用（刷新数据、播放动画）
   - `OnHide()`：窗口隐藏时调用（暂停动画、保存状态）
   - `OnClose()`：窗口关闭时调用（反注册事件）
   - `OnDestroy()`：窗口销毁时调用（清理资源）
   - `OnUpdate()`：每帧调用（可选，默认不启用）
   - `OnSortDepth()`：深度排序变化时调用
   - `OnSetVisible(bool)`：可见性变化时调用

3. **TEngine 优秀设计**：
   - **Canvas.sortingOrder 深度管理**：避免 transform.SetSiblingIndex 频繁重排
   - **layer 切换实现可见性**：比 SetActive(false) 性能更好（不销毁 Canvas 状态）
   - **子 Canvas 递增**：嵌套 Canvas 自动保持相对深度
   - **HideTimeToClose**：隐藏一段时间后自动关闭（优化内存）
   - **IUIResourceLoader 抽象**：解耦资源加载实现（YooAsset/Addressables/Resources）

**TryGet V2.3 设计决策**：
- ✅ 采用 sortingOrder 深度管理（TEngine 验证有效）
- ✅ 采用 layer 切换可见性（性能优于 SetActive）
- ✅ 生命周期方法与 TEngine 对齐（OnCreate/OnShow/OnHide/OnClose/OnDestroy）
- ✅ IUIResourceLoader 抽象（Core 层契约，Unity Adapter 实现）
- ⚠️ 简化：不做 HideTimeToClose（延后到性能优化阶段）
- ⚠️ 简化：OnUpdate 默认不启用（避免性能开销，需要时显式继承 IUpdateModule）

**里程碑**：
- **M1：IUIModule 契约 + UIWindow/UIWidget 基类**（纯 C# Core）
  - 定义 IUIModule / IUIWindow / IUIWidget 接口
  - UIWindow 抽象基类：生命周期虚方法 + 属性定义
  - UILayer 枚举：Background / Normal / Fixed / Popup / System / Guide
  - IUIResourceLoader 接口：LoadAsync / UnloadAsset
  - EditMode 测试：Mock 实现验证生命周期调用顺序

- **M2：层级管理 + 深度排序**（Runtime/Unity Adapter）
  - UIModule 实现：窗口注册表 + 层级分组
  - OpenWindow / CloseWindow / ShowWindow / HideWindow
  - sortingOrder 自动分配 + 子 Canvas 递增
  - layer 切换实现可见性（WINDOW_SHOW_LAYER / WINDOW_HIDE_LAYER）

- **M3：资源绑定 + 异步加载**
  - UnityUIResourceLoader 实现（Resources.LoadAsync）
  - UIWindow 创建流程：LoadAsync Prefab → Instantiate → OnCreate
  - 资源卸载策略：Close 后延迟卸载 / 引用计数

- **M4：窗口栈 + Focus 事件**
  - Push / Pop 窗口栈（对标 ProcedureModule 栈管理）
  - OnFocus / OnLostFocus 事件（栈顶变化时触发）
  - FullScreen 窗口处理：遮挡下层时自动 Hide

- **M5：UIWidget 组件库**
  - UIButton / UIList / UIInput / UIScrollView / UIToggle
  - 事件绑定辅助：AddUIEvent 扩展方法
  - Widget 对象池复用（参考 hsenl UI 面板池）

### 9.2 技术趋势关键发现（2025-2026）

**（workflow web search 部分返回空，基于手动分析补充）**

1. **UniTask vs TGTask**：
   - UniTask 生态成熟（4.5k+ stars，2025 仍活跃维护）
   - TGTask 优势：零依赖、框架自包含、完全可控（C11 池化生命周期收口已验证）
   - **决策**：保持 TGTask，V2.3+ 补全 WhenAll/WhenAny/Timeout 等工具方法对标 UniTask

2. **YooAsset vs Addressables**：
   - YooAsset 2025 年仍是国内主流（商业项目首选，工具链成熟）
   - Addressables Unity 官方但性能/易用性不如 YooAsset（国内社区共识）
   - **决策**：V2.4 优先 YooAsset Adapter

3. **Source Generator 最佳实践**：
   - 增量生成是标准（TryGet C10 已实现）
   - 编译期诊断是趋势（TG0001-TG0006 已对标 Roslyn Analyzer）
   - 生成器源码随框架分发（Generators~ 模式对标 Unity Netcode）
   - **决策**：保持现有设计，V2.3+ 可扩展 UI 绑定代码生成

4. **HybridCLR 2025 现状**：
   - 稳定性大幅提升（2.x 版本生产可用）
   - 工具链成熟（热更包构建、差分更新、加密）
   - **决策**：V2.8 集成时参考 MyFramework/DGame 工具链

## 10. 附录：参考框架 UI 设计对比

### 10.1 TEngine UIWindow 核心设计

**生命周期**（UIBase.cs）：
```csharp
protected virtual void OnCreate()      // 首次创建
protected virtual void OnRefresh()     // 数据刷新
protected virtual void OnUpdate()      // 每帧更新（可选）
protected virtual void OnDestroy()     // 销毁
protected virtual void OnSortDepth()   // 深度变化
protected virtual void OnSetVisible(bool visible)  // 可见性变化
```

**窗口属性**（UIWindow.cs）：
```csharp
string WindowName              // 窗口唯一标识
int WindowLayer                // 层级（Background=0, Normal=1000, Popup=2000）
string AssetName               // 资源定位地址
bool FullScreen                // 是否全屏
int Depth                      // sortingOrder（动态）
bool Visible                   // layer 切换（SHOW_LAYER vs HIDE_LAYER）
Canvas Canvas                  // 主 Canvas
GraphicRaycaster Raycaster     // 射线检测
```

**深度管理**（UIWindow.cs:87-138）：
- 设置 `Depth` 时：
  1. 更新主 Canvas.sortingOrder
  2. 递归更新所有子 Canvas（保持相对深度）
  3. 触发 `OnSortDepth()` 回调

**可见性管理**（UIWindow.cs:143-180）：
- 通过 `layer` 切换而非 `SetActive`：
  - `Visible = true`：`layer = WINDOW_SHOW_LAYER`（默认 5，UI 层）
  - `Visible = false`：`layer = WINDOW_HIDE_LAYER`（自定义隐藏层，如 30）
- 优势：Canvas 状态不销毁，切换性能更好

**资源加载**（IUIResourceLoader.cs）：
```csharp
UniTask<GameObject> LoadWindowAsync(string assetName)    // 异步加载
void UnloadWindow(string assetName, GameObject instance) // 卸载
```

### 10.2 TryGet V2.3 采纳决策

| TEngine 设计 | TryGet V2.3 决策 | 理由 |
|-------------|-----------------|------|
| sortingOrder 深度管理 | ✅ 采纳 | 性能优于 SetSiblingIndex |
| layer 切换可见性 | ✅ 采纳 | 性能优于 SetActive |
| OnCreate/OnDestroy | ✅ 采纳 | 标准生命周期 |
| OnShow/OnHide | ✅ 采纳（改名 OnOpen/OnClose） | 语义更清晰 |
| OnRefresh | ⚠️ 暂不采纳 | 用 OnShow 代替，减少方法数 |
| OnUpdate | ⚠️ 可选启用 | 默认不启用，需要时继承 IUpdateModule |
| HideTimeToClose | ❌ 延后 | 性能优化阶段再考虑 |
| SetUISafeFitHelper | ❌ 不采纳 | 刘海屏适配属于 Unity Adapter 细节 |
| UIBindComponent | ⚠️ V2.3 M5 | Widget 组件库阶段考虑 |
