## 1. 调研结果汇总

### 1.1 资源加载（IAssetSource）

| 框架 | 抽象层 | 后端 | API 风格 |
|------|-------|------|---------|
| TEngine | `IResourceModule` + `ResourceModule` | YooAsset（4 运行模式 + 加密 + 引用计数） | `LoadAssetAsync<T>(loc): UniTask<T>` |
| Fantasy | 无显式抽象 | AppDefine 路径常量 + AssetBundle | 文件未明确 |
| ET | 无显式抽象 | YooAsset 集成 | 同 TEngine |
| BigCat | 无 | — | — |

**关键观察**：YooAsset 是 Unity 生态事实标准（4 个框架里 2 个用），但 TEngine 强绑定 YooAsset 接口（无 swap-out 能力）。

→ **TryGet 决策**：定义 `IAssetSource` 抽象（与 YooAsset 解耦），LoadAsync 返回 `TGTask<T>`（V0.6 异步原语客户），Core 内只做 `MemoryAssetSource`（Dictionary mock），真实 YooAsset / Bundle 实现留 **V1.1+ Adapter**。

### 1.2 配置表（IConfigSource + ConfigLoader<T>）

| 框架 | 方案 | 代码生成 | 加载格式 | 热重载 |
|------|------|---------|---------|--------|
| ET | Luban | Excel → C# class + 二进制 | binary | 服务端无 |
| TEngine | Luban + 自研 `ConfigSystem` | 同 ET，Custom Template | binary | **无** |
| Fantasy | **自研** `ConfigLoader` + Roslyn SourceGen | SceneType/DatabaseName 等常量类 | XML/JSON | **服务端无意义** |
| BigCat | 无 | — | — | — |

**关键观察**：
- Luban 是事实标准（Excel → 多语言代码 + 多格式数据）
- 热重载几乎所有框架都不做（服务端配置启动时定死）
- 类型化 vs 字符串化访问：Luban 走类型化 `Tables.ItemConfig.Get(id)`；Fantasy 也走类型化

→ **TryGet 决策**：定义 `IConfigSource`（无类型 byte[] 数据访问）+ `ConfigLoader<T>`（业务定义 T + 提供反序列化函数 / 用 ISerializer）。**真实 Luban 集成留 V1.1+ Adapter**。`MemoryConfigSource` 直接持 `Dictionary<string, byte[]>` 模拟。

### 1.3 存档/KV（IKVStore）

| 框架 | 后端 | 类型 | 加密 |
|------|------|------|------|
| TEngine | PlayerPrefs（+ 8KB 分片 + 用户隔离） | 弱类型 `GetInt/SetString` | **无** |
| ET 服务端 | MongoDB | 强类型（`ISupportedSerialize`） | 数据库层 |
| Fantasy 服务端 | MongoDB（BSON 序列化） | 强类型（`[BsonId]` + `[SeparateTable]`） | 数据库层 |
| Fantasy 客户端 | 未明确 | — | — |
| BigCat | 无 | — | — |

**关键观察**：服务端强类型 + 数据库 / 客户端弱类型 + PlayerPrefs。两类后端形态本质不同。

→ **TryGet 决策**：`IKVStore` 走**强类型** `Get<T>(key)` / `Set<T>(key, value)` —— 与 ET/Fantasy 服务端一致。`MemoryKVStore` 绕过 ISerializer，直接持 `Dictionary<string, object>`（zero-copy）。`PlayerPrefsKVStore` / `MongoDbKVStore` 等留 **V1.1+ Adapter**。

### 1.4 序列化（ISerializer）

| 库 | 性能 | AOT | 业界采用 | 文件大小 | 备注 |
|---|------|-----|---------|---------|------|
| MemoryPack | **最快**（10-200x 其他） | ✓ Source Gen | Fantasy / 现代 .NET 项目 | float 大 / int 大 | 需 .NET 7+ 或 Unity 2022.3+ |
| MessagePack | 快 | ✓ Source Gen | ET / Unity 业界 | varint 小 | netstandard2.0 OK |
| Protobuf | 中 | ✓ | 跨语言 IDL | 极小 | 无 null 表达 |
| System.Text.Json | 慢 | △ | .NET 标准 | 大（文本） | netstandard2.1 需 NuGet |
| Newtonsoft.Json | 慢 | △ | Unity 旧业界 | 大 | 反射重 |

**关键观察**：MemoryPack 在 Cysharp/MemoryPack 项目中是 Unity 2026 最佳选择（zero encoding + source generator + AOT-safe）。但需要 source generator（与 V0.9 路线重叠）。

→ **TryGet 决策**：
- 定义 `ISerializer` 接口（`Serialize<T>(value): byte[]` + `Deserialize<T>(byte[]): T` + `IsSupported(Type)`）
- **Core 内不提供实现**（避免引入 NuGet 依赖，保持跨端 0 警告 0 错误）
- 测试用 `MockBytesSerializer`（仅在 Tests 目录，把 obj.ToString() 转 UTF-8 bytes 模拟）
- 真实 MemoryPack / Json 实现 → **V1.1+ Adapter**

## 2. API 详细设计

### 2.1 ISerializer

```csharp
namespace TryGet
{
    /// <summary>
    /// 序列化服务契约（V0.8 起）。
    /// Core 内无实现 — 真实序列化（MemoryPack / Json / Protobuf）由 Adapter 提供。
    /// </summary>
    public interface ISerializer : IModule
    {
        /// <summary>查询此 Serializer 是否支持给定类型。</summary>
        bool IsSupported(Type type);

        /// <summary>序列化为 byte[]。不支持的类型抛 NotSupportedException。</summary>
        byte[] Serialize<T>(T value);
        byte[] Serialize(Type type, object value);

        /// <summary>反序列化。不支持类型 / 数据格式错误抛 InvalidOperationException。</summary>
        T Deserialize<T>(byte[] data);
        object Deserialize(Type type, byte[] data);
    }
}
```

### 2.2 IKVStore

```csharp
namespace TryGet
{
    /// <summary>
    /// Key-Value 存储契约（V0.8 起，替代 <see cref="ISaveModule"/>）。
    /// 强类型 Get/Set，序列化由 ISerializer 注入（MemoryKVStore 不需要）。
    /// </summary>
    public interface IKVStore : IModule
    {
        bool ContainsKey(string key);
        bool TryGet<T>(string key, out T value);
        T Get<T>(string key);
        void Set<T>(string key, T value);
        bool Remove(string key);
        void Clear();
        IEnumerable<string> Keys { get; }
    }

    /// <summary>
    /// Memory 实现：绕过 ISerializer，直接持 object。仅测试/headless 用，重启丢失。
    /// </summary>
    public sealed class MemoryKVStore : IKVStore { /* Dictionary<string, object> */ }

    /// <summary>
    /// 把 V0.7 ISaveModule 桥接为 IKVStore（与 LogModuleAdapter 模式一致）。
    /// </summary>
    [Obsolete("Migrate to direct IKVStore. Adapter removed in V0.9.")]
    public sealed class SaveModuleAdapter : IKVStore { /* ... */ }
}
```

### 2.3 IConfigSource + ConfigLoader<T>

```csharp
namespace TryGet
{
    /// <summary>
    /// 配置数据源契约（V0.8 起）。无类型 byte[] 访问；类型化由 ConfigLoader<T> 完成。
    /// </summary>
    public interface IConfigSource : IModule
    {
        bool Has(string configId);
        byte[] GetRaw(string configId);
        IEnumerable<string> ConfigIds { get; }
    }

    /// <summary>
    /// 类型化配置加载器。业务 new ConfigLoader<MyConfig>(source, deserializer)。
    /// 缓存反序列化结果（重复 Get 不重复反序列化）。
    /// </summary>
    public sealed class ConfigLoader<T>
    {
        public ConfigLoader(IConfigSource source, Func<byte[], T> deserializer);
        public T Get(string configId); // 缓存
        public bool TryGet(string configId, out T value);
        public void InvalidateCache(); // 热重载用
    }

    public sealed class MemoryConfigSource : IConfigSource
    {
        // Dictionary<string, byte[]>
        public void SetRaw(string configId, byte[] data); // 测试 / 业务 mock 用
    }
}
```

### 2.4 IAssetSource (async)

```csharp
namespace TryGet
{
    using TryGet.Async;

    /// <summary>
    /// 资源加载契约（V0.8 起）。异步加载 / 与 V0.6 TGTask 集成。
    /// </summary>
    public interface IAssetSource : IModule
    {
        bool IsLoaded(string path);
        TGTask<T> LoadAsync<T>(string path) where T : class;
        T Get<T>(string path) where T : class; // 已加载时直接取，未加载抛
        void Unload(string path);
        IEnumerable<string> LoadedPaths { get; }
    }

    public sealed class MemoryAssetSource : IAssetSource
    {
        // Dictionary<string, object>
        public void Add<T>(string path, T asset) where T : class;
    }
}
```

## 5. 风险点

| # | 风险 | 缓解 |
|---|------|------|
| 1 | `IKVStore.Get<T>` 强类型 vs PlayerPrefs 弱类型阻抗 — 业务用 PlayerPrefs Adapter 时若类型不匹配抛 | Adapter 内部用 ISerializer 跨类型；MemoryKVStore 测试用直接 cast |
| 2 | ConfigLoader<T> 缓存与热重载冲突 — V0.8 不做热重载，但留 `InvalidateCache` API | 测试覆盖：Set 同 id 后 Get 返回旧值；InvalidateCache 后 Get 返回新值 |
| 3 | IAssetSource.LoadAsync 路径不存在 → TGTask 抛或返 default？| 抛 `KeyNotFoundException` 包装到 TGTask（V0.6 TGTaskCompletionSource.SetException） |
| 4 | ISerializer Core 无实现 → ConfigLoader<T> 测试需要业务自己写 deserializer Func | 接受；测试用 lambda 直接写 |
