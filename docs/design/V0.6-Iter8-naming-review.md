# V0.6 Iter 8 — 命名审视与专业化（Naming Review）

> **撰写日期**：2026/05/24
> **状态**：决策文档
> **触发**：用户明确要求"框架所有内容的命名都应该正确"。本文做一次完整公开类型扫描，对照 .NET / UniTask / ETTask / FTask / HTask 命名约定，给出 rename plan。
> **范围**：V0.6 期间可做的命名收紧（Async 层 + Handle）；V0.7+ 计划改名（ILogModule / IResourceModule / ISaveModule / IConfigModule）不在本文范围。

## 1. 命名约定基线

### 1.1 C# 官方约定（Microsoft Framework Design Guidelines）

| 形态 | 前缀 | 示例 |
|---|---|---|
| Interface | **`I` 前缀强制** | `IDisposable` / `IEnumerable<T>` |
| Class / Struct / Enum | **禁止 `I` 前缀** | `Stream` / `Vector3` / `LogLevel` |
| Abstract class | 通常带 `Base` 后缀 | `Stream` (abstract) / `ProcedureBase` |
| Exception | `Exception` 后缀 | `InvalidOperationException` |
| Async 方法 | `Async` 后缀 | `ReadAsync()` |
| 静态工厂 | `From*` / `Create*` | `Task.FromResult` / `String.Create` |

### 1.2 游戏框架异步原语前缀风格

| 框架 | 异步类型 | 前缀 |
|---|---|---|
| .NET | `Task` / `ValueTask` | 无 |
| UniTask | `UniTask` | `Uni` |
| ETTask | `ETTask` | `ET` |
| Fantasy | `FTask` | `F` |
| Hsenl | `HTask` | `H` |
| **TryGet（本次确定）** | **`TGTask`** | **`TG`**（TryGet 缩写） |

理由：单/双字母前缀风格统一，避免与 .NET 标准库 `Task` 重名造成 using 冲突，与同代框架（ET/F/H）保持识别度。

## 3. 配套增强（参考其他框架的方法命名）

### 3.1 静态工厂（参考 .NET `Task.FromResult` + UniTask `UniTask.CompletedTask`）

```csharp
public partial struct TGTask
{
    /// <summary>已完成的空 task 单例。等价 default(TGTask) 但语义更明确。</summary>
    public static TGTask CompletedTask => default;

    /// <summary>立即完成、带值的 TGTask&lt;T&gt;。</summary>
    public static TGTask<T> FromResult<T>(T value);

    /// <summary>立即完成、抛指定异常的 TGTask。</summary>
    public static TGTask FromException(Exception exception);
    public static TGTask<T> FromException<T>(Exception exception);

    /// <summary>立即完成、已取消的 TGTask（抛 OperationCanceledException）。</summary>
    public static TGTask FromCanceled();
    public static TGTask<T> FromCanceled<T>();
}
```

对标：
- .NET `Task.CompletedTask` / `Task.FromResult` / `Task.FromException` / `Task.FromCanceled`
- UniTask `UniTask.CompletedTask` / `UniTask.FromResult` / `UniTask.FromException` / `UniTask.FromCanceled`
- ETTask `ETTask.CompletedTask`

### 3.2 全局异常钩子（参考 UniTask `UniTaskScheduler.UnobservedTaskException`）

```csharp
public static class TGTaskScheduler
{
    /// <summary>
    /// 未观察到的 TGTask 异常的全局钩子。
    /// 触发条件：TGTask.Forget() 被调用后内部发生异常。
    /// 用法：业务在 Bootstrap 时订阅，统一上报到 LogModule。
    /// </summary>
    public static event Action<Exception> UnobservedException;
}
```

### 3.3 `TGTask.Forget()` 真实实现

V0.6 Iter 1 的 `Forget()` 是 no-op。Iter 8 改为：
- 标记此 task 已显式 fire-and-forget
- 内部异常进入 `TGTaskScheduler.UnobservedException` 全局钩子
- 业务可在 Bootstrap 时统一接 Logger

## 4. 风险评估

| # | 风险 | 缓解 |
|---|---|---|
| 1 | rename 量大（Async 15 + Entity 1 + 测试 7 + 引用文件 5+）一次提交 review 困难 | 单 commit 完成，附详尽 CHANGELOG，rename 是纯语义变更不带逻辑改动 |
| 2 | Unity 端 .meta GUID 关联（git mv）丢失 | V0.6 还未在 Unity 端跑过，.meta 自动重生成不影响 |
| 3 | 外部业务代码引用 `ITask` 已存在 | V0.6 还未 release，无外部代码 |
| 4 | 文档（V2 设计文档 / Roadmap / V0.6 PRD / CHANGELOG）引用旧名 | 跟随更新 |
| 5 | rename 后某处遗漏导致编译失败 | Shadow csproj `dotnet build` 100% 覆盖 Core，遗漏会立刻发现 |
