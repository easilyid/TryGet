## 1. 调研结果汇总

### 1.1 IPlugin 切面机制（hsenl 唯一参考）

| 框架 | IPlugin 抽象？ | 实现细节 |
|------|---------------|---------|
| **hsenl** | **有** | `IPlug` (Init/Dispose) + `IPluggable` (AddPlug/RemovePlug/GetPlug) + `IPlugGroup` 标记接口 + 7 个网络生命周期接口（IOnChannelStarted / IOnRecvData 等） |
| Fantasy | 无（用 IEntitySystem 接口注册） | — |
| ET | 无 | — |
| TEngine | 无 | — |
| BigCat | 无 | — |
| Microsoft.Extensions.Hosting | `IHostedService`（生命周期）+ `IServiceCollection`（DI） | 工业标准但太重 |

**hsenl IPlug 使用模式**（来自 ReferenceFramework/hsenl 调研）：
```csharp
public class TrafficMonitoringPlug : IPlug, IOnChannelStarted, IAfterMessageReaded
{
    public void Init(IPluggable pluggable) { /* 初始化 */ }
    public void Dispose() { /* 清理 */ }
    void IOnChannelStarted.Handle(long channelId) { /* 横切点 */ }
    void IAfterMessageReaded.Handle(channel, data) { /* 横切点 */ }
}

server.AddPlug<IOnChannelStarted, TrafficMonitoringPlug>(plug);
server.AddPlug<IAfterMessageReaded, TrafficMonitoringPlug>(plug);
```

**关键观察**：
- 一个 plug 可同时实现多个 IPlugGroup（多个横切点）
- AddPlug 自动 Init，RemovePlug 自动 Dispose
- Dictionary 存储，遍历无序（无 Priority）

→ **TryGet 决策**：吸收 hsenl 设计但**简化 + 通用化**：
- `IPlugin` 基础接口（Install/Uninstall 命名比 Init/Dispose 更清晰）
- `IPluginHost` 接口（替代 IPluggable，TryGet 统一命名）
- `IPlugPoint` 标记接口（替代 IPlugGroup，命名表意更明确）
- **挂在 ModuleHost 上**（hsenl 是 Service；TryGet 挂 ModuleHost，覆盖范围更广 — ModuleHost 是框架根容器）
- **Priority 字段**（hsenl 无 Priority，TryGet 加入与 Module 体系对齐）
- 一个 demo plug：`ModuleHostMetricsPlugin`（钩 Initialize/Update/Shutdown 计 Module 调用次数）

### 1.2 IPureComponent / ECS 二级方案

**ET 纯数据路线 vs TryGet Aspect-with-methods 现状**：

| 框架 | ECS 方案 | Component 是否含行为？ |
|------|---------|----------------------|
| **TryGet 当前** | Aspect（含 OnAttach/OnDetach + 自定义方法） | **是** — 行为内嵌 Aspect |
| **ET** | Component（纯 POCO，零方法） | **否** — 行为在 System |
| Fantasy | 同 ET | 否 |
| TEngine | 同 ET（基于 GameFramework） | 否 |

**两条路线各自的优缺点**：

| 维度 | Aspect（TryGet 当前） | IPureComponent（ET 路线） |
|------|---------------------|------------------------|
| 行为内聚 | ✓ 数据 + 行为同位置 | ✗ 行为在 System |
| 测试单元 | ✗ Aspect 单测需 Entity 上下文 | ✓ Pure POCO 易测 |
| Source Gen 友好 | ✗ 行为方法难自动生成 | ✓ Component + IComponentSystem 模式 |
| 业务直觉 | ✓ OO 风格 | ✗ 数据/行为分离需学习 |

→ **TryGet 决策**：**两条路线并存**（不替换）：
- 保留现有 Aspect-with-methods（V0.1-V0.8 业务代码不变）
- **新增** `IPureComponent`（标记接口 + 无方法约束）+ `IComponentSystem<T>` 外置行为接口
- 业务可选 Aspect（OO）或 PureComponent + System（ET 风格）
- 写 `ADR-0017` 文档化此分歧（"为何 TryGet 不走纯数据 Component"）

## 2. API 详细设计

### 2.1 IPlugin

```csharp
namespace TryGet
{
    /// <summary>
    /// 横切关注点插件基础接口（V0.9 起，吸收 hsenl IPlug 设计）。
    /// 命名升级：Init/Dispose → Install/Uninstall（更明确表达 plug 语义）。
    /// </summary>
    public interface IPlugin
    {
        void Install(IPluginHost host);
        void Uninstall(IPluginHost host);
        int Priority { get; } // hsenl 没有，TryGet 加入与 Module 一致
    }

    /// <summary>插件宿主契约。ModuleHost 实现此接口让自己可挂插件。</summary>
    public interface IPluginHost
    {
        void AddPlugin<TPoint, T>(T plugin) where TPoint : IPlugPoint where T : IPlugin, TPoint;
        bool RemovePlugin<TPoint, T>() where TPoint : IPlugPoint where T : IPlugin, TPoint;
        T GetPlugin<TPoint, T>() where TPoint : IPlugPoint where T : IPlugin, TPoint;
        IEnumerable<TPoint> GetPluginsAt<TPoint>() where TPoint : IPlugPoint;
    }

    /// <summary>插点标记接口。业务定义具体插点（IModuleHostBeforeUpdate 等）。</summary>
    public interface IPlugPoint { }
}
```

**ModuleHost 集成**：
- `ModuleHost` 实现 `IPluginHost`
- 内部 `Dictionary<Type, List<IPlugin>>`（TPoint → 已注册插件）
- AddPlugin 时自动 Install，按 Priority 排序后保存
- RemovePlugin 时自动 Uninstall

**Demo 插点**：
- `IModuleHostBeforeUpdate : IPlugPoint` — `void Handle(IModuleHost host, float dt, float udt)`
- `IModuleHostAfterUpdate : IPlugPoint` — 同上
- ModuleHost.Update 内部按顺序触发：BeforeUpdate plugins → IUpdateModule.Update → AfterUpdate plugins

**Demo Plugin**：
- `ModuleHostMetricsPlugin : IPlugin, IModuleHostBeforeUpdate, IModuleHostAfterUpdate`
- 统计 Update 调用次数、累计 dt、平均帧耗时
- 业务：`host.AddPlugin<IModuleHostBeforeUpdate, ModuleHostMetricsPlugin>(p)`

### 2.2 IPureComponent + IComponentSystem<T>

```csharp
namespace TryGet
{
    /// <summary>
    /// 纯数据 Component 标记接口（V0.9 起，ECS 二级方案，参考 ET）。
    ///
    /// 行为约束（编译期无强制，运行期 Entity 内置检查 + ADR-0017 风格指南）：
    /// - 不应有方法 / 属性 setter（业务用 IComponentSystem<T> 操作）
    /// - 应是 POCO struct 或 class
    /// - 不持引用外部 Aspect / Module
    ///
    /// 与 Aspect 对比：
    /// - Aspect：OO 风格，行为内聚（OnAttach/OnDetach + 自定义方法），数据 + 行为同实例
    /// - IPureComponent：ET 风格，行为外置到 IComponentSystem<T>，数据/行为分离
    /// - 两条路线并存，业务按场景选
    /// </summary>
    public interface IPureComponent { }

    /// <summary>
    /// 外置 System 操作 IPureComponent（参考 ET IEventSystem<C, E>）。
    /// 业务实现 IComponentSystem<MyComponent> 提供 OnAttach/OnUpdate 等行为。
    /// </summary>
    public interface IComponentSystem<TComponent> where TComponent : IPureComponent
    {
        void OnAttach(Entity entity, TComponent component);
        void OnDetach(Entity entity, TComponent component);
    }

    public static class EntityPureComponentExtensions
    {
        public static void AddComponent<T>(this Entity entity, T component) where T : IPureComponent;
        public static T GetComponent<T>(this Entity entity) where T : IPureComponent;
        public static bool HasComponent<T>(this Entity entity) where T : IPureComponent;
        public static bool RemoveComponent<T>(this Entity entity) where T : IPureComponent;
    }
}
```

**实现策略**：
- Entity 内部维护新的 `Dictionary<Type, IPureComponent>`（与 `_aspects` 并存）
- AddComponent 时不调 OnAttach（Component 无方法）；用户业务通过 `system.OnAttach(entity, component)` 显式触发
- **V0.9 不引入 IComponentSystem 自动调度**（避免与 SystemGroup 复杂耦合，V0.9.5 + Source Generator 后再做）
- Component 存储与 Aspect 隔离：`entity.GetAspect<T>` 与 `entity.GetComponent<T>` 完全独立

**ADR-0017 要点**：
- 为何 TryGet 走双轨而非 ET 单纯数据：考虑现有业务 + Aspect OO 风格的可用性
- IPureComponent 的取舍：标记接口（无强制约束）+ 文档纪律
- Aspect vs IPureComponent 何时用哪个：
  - 行为复杂、内聚强 → Aspect
  - 数据简单、System 操作 → IPureComponent
- V1.0+ 路线：评估能否用 Source Generator 在 IPureComponent 上自动生成 IComponentSystem 调度

## 5. 风险点

| # | 风险 | 缓解 |
|---|------|------|
| 1 | IPlugin 与现有 IModule 概念混淆（都是"组件"） | 文档明确：Module = 服务（host.Get<T>()），Plugin = 横切（hook 到插点） |
| 2 | IPureComponent 与 Aspect 并存导致用户困惑 | ADR-0017 详述选择矩阵 + 示例代码 |
| 3 | ModuleHost.AddPlugin Priority 排序与 Module Priority 拓扑序耦合 | Plugin Priority 仅在同 IPlugPoint 内排序，与 Module Priority 独立 |
| 4 | IComponentSystem<T> V0.9 不引入自动调度可能让 PureComponent 落地体验差 | 文档明确"V0.9 是接口/契约 minor，自动调度留 V0.9.5 Source Gen" |
