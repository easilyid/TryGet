## 1. 调研结果汇总

### 1.1 入口规范跨框架对比

| 框架 | Unity 端入口 | .NET 端入口 | IEntry interface？ |
|------|-------------|-------------|-------------------|
| Fantasy | `Fantasy.Platform.Unity.Entry` (MonoBehaviour) | `Fantasy.Platform.Console.Entry` (static) | **无** |
| ET | `Init.cs` / `Game.cs` (MonoBehaviour) | `Program.cs` (static) | **无** |
| BigCat | `GameLauncher` (MonoBehaviour) + `AppContext` (static) | 同 GameLauncher 经 builder | **无** |
| TEngine | `GameEntry` (MonoBehaviour) | — Unity-only | **无** |
| hsenl | — | — | **无** |

**关键结论**：没有一个商业框架定义 `IEntry` interface。原因：MonoBehaviour 启动器和 static Main 的接口签名本质不同（前者无返回，后者 int Main(args)），强行抽象 interface 增加心智成本不带来灵活性。

→ **TryGet 决策**：**不定义 IEntry interface**。改为 **`Bootstrap` 静态工具类** + **平台特定 Entry 类**（`TryGet.Platform.Net.Entry` + 留 V1.0+ 加 Unity 端的 `TryGet.Platform.Unity.Entry`）。

### 1.2 日志接口跨框架对比

| 框架 | 接口名 | 方法风格 | LogLevel |
|------|--------|---------|----------|
| Fantasy | `ILog` | Trace/Debug/Info/Warning/Error | enum |
| hsenl | `ILog` | 同上 | enum |
| TEngine | `ILogHelper` | `Log(level, message)` 单方法 | `GameFrameworkLogLevel` |
| BigCat | — | 借用 Wjybxx.Commons | — |
| .NET (Microsoft.Extensions.Logging) | `ILogger` | `Log(level, eventId, state, ex, formatter)` + extension methods `LogTrace/LogDebug/...` | `LogLevel` enum (Trace/Debug/Information/Warning/Error/Critical/None) |
| 现代 Unity (ZLogger) | `ZLogger` extends MEL | structured logging + UTF8 + zero-alloc | 同 MEL |

**关键结论**：
- 商业 Unity 框架命名 `ILog`，.NET 生态标准 `ILogger`
- `ILogger`（MEL）功能丰富但泛型 `ILogger<T>` + factory 模式偏重
- 简单方法签名（`Info(string)`）vs 结构化日志（`Info("user {id}", id)`）二选一

→ **TryGet 决策**：
- 接口名 **`ILogger`**（.NET 现代标准，避免与 V0.7+ 可能引入 MEL bridge 的命名冲突）
- 方法签名：**`Trace/Debug/Info/Warn/Error(string)` + `Error(string, Exception)`**（hsenl 风格，简单）
- `LogLevel` enum 命名 **`Trace/Debug/Info/Warn/Error`**（与现有 `ILogModule.LogLevel` 兼容，不用 MEL 的 Information/Warning/Critical）
- **不做** structured logging（V1.0+ 评估）
- **不做** 泛型 `ILogger<T>` + factory（过度设计）
- 现有 `ILogModule` 标记 `[Obsolete("Use ILogger instead. Bridge LogModuleAdapter 保留到 V0.8")]`
- `LogModuleAdapter` bridge：把 `ILogModule` 适配为 `ILogger`（让现有代码无痛迁移）

### 1.3 时钟抽象跨框架对比

| 框架 | 时钟抽象？ | 实现 |
|------|-----------|------|
| BigCat | **有** `TimeModule` | `Update(curTime) / FrameCount / Time / DeltaTime / TimeSinceStarted`（long ms） |
| Fantasy | 无 | Unity 端读 `Time`，Net 端 `TimeHelper.Now` |
| ET | 无 | 直接读 `Time` / `DateTime` |
| TEngine | 无 | 直接读 `Time.deltaTime` |
| hsenl | 无 | 直接读 |
| UniTask | 无 | hook PlayerLoop + 直接读 `Time` |
| .NET 8+ | 有 `TimeProvider` | `GetUtcNow / GetTimestamp / GetElapsedTime` — wall-clock 取向 |

**关键结论**：
- 大部分 Unity 框架不抽象时钟，BigCat 是唯一例外
- .NET 8 `TimeProvider` 是 wall-clock 取向（DateTime），不适合 game frame dt
- 游戏框架需要的是 **frame dt + frame count + elapsed time** 三件套

→ **TryGet 决策**：
- 定义 **`IClock`** 接口：`DeltaTime / UnscaledDeltaTime / ElapsedTime / UnscaledElapsedTime / FrameCount` — game frame 取向
- **不暴露 `UtcNow`**（V0.8 Network 时再加 IWallClock 或挂 IClock 上的 IWallTimeService）
- **`SystemClock`**（Net）：由外部 host.Update(dt, udt) 注入累加；`FrameCount += 1`
- **`UnityClock`**（Adapter 在 Samples/Unity，V1.0+ 加）：read `Time.deltaTime / .unscaledDeltaTime / .frameCount`
- **不破坏** `IUpdateModule.Update(dt, udt)` 签名（向后兼容）— Module 选择性从 host.Get<IClock>() 读"非当前帧 dt 的时钟信息"（如 FrameCount / ElapsedTime）

**架构判断 — 为什么不去掉 Update(dt, udt) 参数？**
- 现存所有 IUpdateModule 实现都接 (dt, udt)，去掉等于全 V0.5/V0.6 Module 重写
- (dt, udt) 是当前帧调度信号，IClock 是"全局时钟状态查询"，**职责本就不同**
- BigCat TimeModule.Update(curTime) 是 IClock 自身的喂数路径，与 Module Update(dt) 也是分离的

### 1.4 EventScope 跨框架对比

| 框架 | EventScope？ |
|------|------------|
| 所有 5 个参考框架 | **无** |
| Microsoft.Extensions.Logging | 有 `BeginScope(state) : IDisposable`（**logging 上下文**，不是 EventBus） |

**关键结论**：EventScope 是 TryGet 创新点。

→ **TryGet 决策**：
- 定义 **`IEventScope : IDisposable`** — Dispose 时批量解绑所有该 scope 内的订阅
- 扩展现有 `IEventBus.Subscribe<T>(handler)` 为 `Subscribe<T>(handler, scope)` overload
- 现有不带 scope 的 Subscribe API **保留**（与 ETTask/Fantasy 风格一致，非破坏）
- 测试：scope.Dispose → handler 不再触发；多 scope 隔离；scope 重复 Dispose no-op

## 2. API 详细设计

### 2.1 IClock

```csharp
namespace TryGet
{
    /// <summary>
    /// 时钟服务契约。游戏帧时间 + 帧计数 + 累计时长。
    /// 不暴露 wall-clock (UtcNow)，避免 Net/Unity 端语义分裂。
    /// </summary>
    public interface IClock : IModule
    {
        /// <summary>当前帧的 scaled deltaTime（受 timeScale 影响）。</summary>
        float DeltaTime { get; }

        /// <summary>当前帧的 unscaled deltaTime（不受 timeScale 影响）。</summary>
        float UnscaledDeltaTime { get; }

        /// <summary>累计 scaled 已运行秒数（每帧累加 DeltaTime）。</summary>
        double ElapsedTime { get; }

        /// <summary>累计 unscaled 已运行秒数。</summary>
        double UnscaledElapsedTime { get; }

        /// <summary>累计帧数（从 0 开始；每帧 +1）。</summary>
        long FrameCount { get; }
    }

    /// <summary>
    /// IClock 的 Net 实现：由外部喂 dt（通常通过 ModuleHost 主循环每帧调 Tick）。
    /// Priority=-900（介于 Log=-1000 和其他 Module 之前）。
    /// </summary>
    public sealed class SystemClock : IClock, IUpdateModule
    {
        public int Priority => -900;
        public IReadOnlyList<Type> DependsOn => Array.Empty<Type>();
        public float DeltaTime { get; private set; }
        public float UnscaledDeltaTime { get; private set; }
        public double ElapsedTime { get; private set; }
        public double UnscaledElapsedTime { get; private set; }
        public long FrameCount { get; private set; }

        public void OnInit(IModuleHost host) { }
        public void Shutdown()
        {
            DeltaTime = 0; UnscaledDeltaTime = 0;
            ElapsedTime = 0; UnscaledElapsedTime = 0;
            FrameCount = 0;
        }

        public void Update(float deltaTime, float unscaledDeltaTime)
        {
            DeltaTime = deltaTime;
            UnscaledDeltaTime = unscaledDeltaTime;
            ElapsedTime += deltaTime;
            UnscaledElapsedTime += unscaledDeltaTime;
            FrameCount++;
        }
    }
}
```

**注意**：`SystemClock` 既是 IClock 也是 IUpdateModule。`host.Update(dt, udt)` 触发 `SystemClock.Update` 累加，其他 Module 通过 `host.Get<IClock>()` 读快照。

### 2.2 ILogger

namespace TryGet

### 2.3 Bootstrap + Net Entry

```csharp
namespace TryGet
{
    /// <summary>
    /// Bootstrap 静态工具：标准化 ModuleHost 创建 + 注册基础 Module + Initialize 顺序。
    /// Unity 端和 Net 端共享，差异在于 Adapter 注册（如 UnityLogger vs ConsoleLogger）。
    /// </summary>
    public static class Bootstrap
    {
        /// <summary>
        /// 创建 ModuleHost 并注册 Core 基础三件套（IClock + ILogger + TGTaskScheduler）。
        /// 业务调用后再 host.Register&lt;其他 Module&gt; + host.Initialize()。
        /// </summary>
        public static IModuleHost CreateHost(BootstrapOptions options = null)
        {
            options ??= BootstrapOptions.Default;
            var host = new ModuleHost();
            host.Register<ILogger>(options.Logger ?? new ConsoleLogger { MinimumLevel = options.MinimumLogLevel });
            host.Register<IClock>(options.Clock ?? new SystemClock());
            host.Register<ITGTaskScheduler>(options.Scheduler ?? new TGTaskScheduler());
            return host;
        }
    }

    /// <summary>
    /// Bootstrap 配置（可选自定义注入 Logger/Clock/Scheduler 实例）。
    /// </summary>
    public sealed class BootstrapOptions
    {
        public static BootstrapOptions Default => new BootstrapOptions();
        public ILogger Logger { get; set; }
        public IClock Clock { get; set; }
        public ITGTaskScheduler Scheduler { get; set; }
        public LogLevel MinimumLogLevel { get; set; } = LogLevel.Info;
    }
}
```

**Net Entry**（放在 `Samples/Net/Entry.cs`，Net 端模板）：
```csharp
namespace TryGet.Samples.Net
{
    /// <summary>
    /// Net 端启动模板。业务用 Entry.Run(setupCallback) 启动框架。
    /// 不定义 IEntry interface（参考 Fantasy/ET 实践）；Unity 端的 Entry 是 MonoBehaviour 形态。
    /// </summary>
    public static class Entry
    {
        public static int Run(
            Action<IModuleHost> setup,
            Func<IModuleHost, TGTask> mainAsync,
            int frameSleepMs = 16,
            long timeoutMs = -1)
        {
            var host = Bootstrap.CreateHost();
            setup?.Invoke(host);
            host.Initialize();

            var clock = host.Get<IClock>();
            var logger = host.Get<ILogger>();

            var mainTask = mainAsync(host);
            var sw = Stopwatch.StartNew();
            long lastMs = 0;
            try
            {
                while (!mainTask.IsCompleted)
                {
                    long nowMs = sw.ElapsedMilliseconds;
                    float dt = (nowMs - lastMs) / 1000f;
                    lastMs = nowMs;
                    host.Update(dt, dt);

                    if (timeoutMs > 0 && nowMs > timeoutMs)
                    {
                        logger.Error($"mainAsync timeout {timeoutMs}ms");
                        return 2;
                    }
                    Thread.Sleep(frameSleepMs);
                }
                try { mainTask.GetAwaiter().GetResult(); }
                catch (Exception ex) { logger.Error("mainAsync threw", ex); return 1; }
                return 0;
            }
            finally { host.Shutdown(); }
        }
    }
}
```

**关键决策**：
- `Entry.Run` 接受 `setup` callback（业务注册自定义 Module）+ `mainAsync` callback（业务异步主流程）
- frameSleepMs = 16 默认 ~60FPS；timeoutMs = -1 默认无超时（生产服务器无限运行）
- `Samples/Net/Program.cs` 重构为：`Entry.Run(host => { ... }, async host => { ... });` 三行调用

### 2.4 IEventScope

```csharp
namespace TryGet
{
    /// <summary>
    /// 事件订阅作用域。Dispose 时批量解绑所有通过此 scope 注册的 handler。
    /// 创新点：参考框架（TEngine/hsenl/Fantasy/ET）均未实现此机制，订阅泄漏需手动 Unsubscribe。
    /// </summary>
    public interface IEventScope : IDisposable
    {
        bool IsDisposed { get; }
    }

    /// <summary>
    /// IEventBus 扩展：Subscribe 带 scope overload。
    /// 现有不带 scope 的 Subscribe 保留共存。
    /// </summary>
    public static class EventBusScopeExtensions
    {
        public static void Subscribe<T>(this IEventBus bus, Action<T> handler, IEventScope scope) where T : struct
        {
            if (scope == null) throw new ArgumentNullException(nameof(scope));
            bus.Subscribe(handler);
            ((EventScope)scope).Register(() => bus.Unsubscribe(handler));
        }

        public static IEventScope CreateScope(this IEventBus bus) => new EventScope();
    }

    /// <summary>
    /// IEventScope 默认实现。
    /// </summary>
    internal sealed class EventScope : IEventScope
    {
        private readonly List<Action> _unsubscribers = new List<Action>();
        public bool IsDisposed { get; private set; }

        internal void Register(Action unsubscriber) => _unsubscribers.Add(unsubscriber);

        public void Dispose()
        {
            if (IsDisposed) return;
            IsDisposed = true;
            for (int i = _unsubscribers.Count - 1; i >= 0; i--)
            {
                try { _unsubscribers[i](); } catch { /* 吞 unsubscribe 异常 */ }
            }
            _unsubscribers.Clear();
        }
    }
}
```

**EntityWorld.Subscribe 类似扩展**：`Entity.Subscribe<T>(handler, scope)` overload。

## 5. 已知风险点 + 缓解

| # | 风险 | 缓解 |
|---|------|------|
| 1 | `ILogger` 与 `Microsoft.Extensions.Logging.ILogger` 重名 → using 冲突 | V0.7 不引 MEL；命名空间 `TryGet.ILogger` 与 `Microsoft.Extensions.Logging.ILogger` 通过 using alias 解 |
| 2 | `IClock` Priority=-900 vs `ConsoleLogger.Priority=-1000` 拓扑顺序 | Logger 先于 Clock 初始化 OK（Logger 不依赖 Clock） |
| 3 | `Bootstrap.CreateHost` 注册顺序写死，业务想换 ITGTaskScheduler 必须传 options | BootstrapOptions 提供 fluent override；或业务跳过 Bootstrap 直接 `new ModuleHost()` |
| 4 | `IEventScope.Dispose` 内部 unsubscribe 抛异常 → 部分订阅未清理 | 用 for + try/catch + 继续遍历，确保尽量多 unsubscribe |
| 5 | `LogModuleAdapter` 桥接性能问题（一次日志 2 次虚调用）| Obsolete 路径不优化；用户应直接用 ILogger |
| 6 | 没有 IEntry interface 是否会让用户困惑 | 文档明确"参考 Fantasy/ET 实践，interface for entry 是过度设计" |
