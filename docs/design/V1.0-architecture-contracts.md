### 1.2 网络抽象层对标（最核心调研）

| 框架 | 抽象层 | 协议覆盖 | 中间件机制 |
|------|--------|---------|----------|
| **hsenl** | `Channel`（abstract） + `KcpChannel` + `TcpChannel` + `Service` + `IPlug` 中间件 | TCP / KCP | **IPlug 管道**（IOnChannelStarted / IOnRecvData / IAfterMessageReaded 等 7 个 IPlugGroup） |
| **ET** | `AService` + `Session` + `Component` 形态 + `LocationProxy` Actor | TCP / KCP / WebSocket / HTTP | Component 风格挂行为 |
| **Fantasy** | `Session` + `NetworkProtocolType` 枚举 | TCP / KCP / WS / HTTP | 单 Session 类 + 协议切换 |
| **TEngine** | 无 Core 层（业务 Unity 端用 KCP 包） | KCP | 无 |
| **MagicOnion** | gRPC + MessagePack | TCP/HTTP/2 | gRPC 拦截器 |

**hsenl Channel 抽象关键点**（`ReferenceFramework/hsenl/HsenlFramework/Network/Common/Channel/Channel.cs`）：
```csharp
public abstract class Channel : IDisposable {
    public long ChannelId { get; private set; }
    public Service Service { get; internal set; }
    internal event Action<long, Memory<byte>> OnMessageReadedEvent;
    internal abstract Memory<byte> GetRecvBuffer(int len);
    internal abstract void Read(Memory<byte> data);
    internal abstract void Write(byte[] data, int offset, int count);
}
```

**hsenl IPlug 集成点**（每个 IPlugGroup 是一个网络生命周期事件）：
- `IOnChannelStarted` — 连接建立
- `IOnChannelDisconnected` — 连接断开
- `IOnRecvData` — 收到原始字节
- `IAfterMessageReaded` — 反序列化后业务消息可见
- `IOnError` — 错误回调
- ... 7 个总共

→ **TryGet 决策**：吸收 hsenl 三件套（Channel/Service/IPlug 网络生命周期）并**对齐 V0.9 已落地的 IPlugin/IPluginHost/IPlugPoint** — 网络层的 7 个 IPlugGroup 就是 7 个 IPlugPoint，业务通过 [IPlugin] 挂中间件无侵入。

### 2.2 INetClient / INetServer / INetMessage 抽象

**核心契约**（放 `Runtime/Core/Net/` 新建目录）：

```csharp
namespace TryGet
{
    /// <summary>客户端连接抽象。一个 INetClient 对应一条到服务端的逻辑通道。</summary>
    public interface INetClient : IDisposable
    {
        ConnectionId Id { get; }
        ConnectionState State { get; }

        TGTask ConnectAsync(string host, int port);
        TGTask DisconnectAsync();

        void Send<T>(T message) where T : INetMessage;

        event Action<ConnectionState> OnStateChanged;
        event Action<INetMessage> OnMessageReceived;
        event Action<Exception> OnError;
    }

    /// <summary>服务端监听抽象。一个 INetServer 接受多个客户端连接。</summary>
    public interface INetServer : IDisposable
    {
        TGTask StartAsync(string bindAddress, int port);
        TGTask StopAsync();

        IReadOnlyCollection<IConnection> Connections { get; }

        event Action<IConnection> OnClientConnected;
        event Action<IConnection> OnClientDisconnected;
        event Action<IConnection, INetMessage> OnMessageReceived;
        event Action<Exception> OnError;
    }

    /// <summary>服务端单个客户端连接。</summary>
    public interface IConnection
    {
        ConnectionId Id { get; }
        ConnectionState State { get; }

        void Send<T>(T message) where T : INetMessage;
        TGTask CloseAsync();
    }

    /// <summary>网络消息标记接口。具体协议序列化由 V1.1+ Adapter（MemoryPack / Protobuf）实现。</summary>
    public interface INetMessage { }

    public readonly struct ConnectionId : IEquatable<ConnectionId>
    {
        public readonly long Value;
        public ConnectionId(long value) { Value = value; }
        // IEquatable 实现略
    }

    public enum ConnectionState
    {
        Disconnected,
        Connecting,
        Connected,
        Disconnecting,
        Faulted,
    }
}
```

**生命周期 IPlugPoint**（与 V0.9 IPlugin 集成）：

```csharp
namespace TryGet
{

    {

    }

    {

    }
}
```

**Core 不含具体实现**：
- INetClient / INetServer / IConnection / INetMessage 是契约 only
- IPlugPoint 派生接口是契约 only
- KCP / LiteNetLib / TCP / WebSocket 实现都留 V1.1+ Adapter

### 2.3 ITickLoop / IFrameLoop 双端时间抽象

```csharp
namespace TryGet
{
    /// <summary>
    /// 服务端 fixed-tick 循环抽象（30/60 Hz 常量步长）。
    ///
    /// 与 V0.7 <see cref="IClock"/> 关系：
    /// - IClock = 时间查询（DeltaTime / ElapsedTime / FrameCount）— 已有
    /// - ITickLoop = 时间驱动（"现在该 tick 一次了"）— V1.0 新增
    ///
    /// 服务端业务实现 ITickLoop.Tick，被 driver 按 TickInterval 周期回调。
    /// </summary>
    public interface ITickLoop
    {
        /// <summary>每 tick 间隔（秒）。常量，启动后不变。</summary>
        float TickInterval { get; }

        /// <summary>本次 tick 业务回调。dt 总等于 TickInterval（不变步长）。</summary>
        void Tick(float dt);
    }

    /// <summary>
    /// 客户端可变-帧循环抽象（Unity Update 风格）。
    ///
    /// 与 ITickLoop 区别：dt 是 Unity 上一帧实际耗时（vsync / 不稳定），非常量。
    /// </summary>
    public interface IFrameLoop
    {
        void Frame(float deltaTime, float unscaledDeltaTime);
    }
}
```

**V1.0 暂不引入 driver 实现**（如 `ServerTickDriver` / `UnityFrameDriver`），仅契约。业务自行用 `Task.Delay(TickInterval)` 循环或 Unity MonoBehaviour.Update 桥接。

### 2.4 双端 Entry 标准化

**Net 端**（V0.7 已有，本 Iter 仅润色）：
- `Samples/Net/Entry.Run(setup, mainAsync, options, frameSleepMs, timeoutMs)` 入口
- 业务 `Main()` 调 `Entry.Run` 后返回 int

**Unity 端**（V1.0 新增）：
- `Samples/Unity/Entry/TryGetMonoEntry.cs` — MonoBehaviour 抽象 base
- 业务子类 override `Setup(IModuleHost host)` 注册自己的 Module
- Mono Awake / Update / OnDestroy 驱动 host.Initialize / host.Update / host.Shutdown

```csharp
namespace TryGet.Samples.Unity
{
    public abstract class TryGetMonoEntry : MonoBehaviour
    {
        protected IModuleHost Host { get; private set; }

        protected virtual BootstrapOptions Options => BootstrapOptions.Default;
        protected abstract void Setup(IModuleHost host);

        private void Awake()
        {
            DontDestroyOnLoad(gameObject);
            Host = Bootstrap.CreateHost(Options);
            Setup(Host);
            Host.Initialize();
        }

        private void Update() => Host?.Update(Time.deltaTime, Time.unscaledDeltaTime);
        private void LateUpdate() => Host?.LateUpdate(Time.deltaTime, Time.unscaledDeltaTime);
        private void OnDestroy() => Host?.Shutdown();
    }
}
```

业务用法：
```csharp
public sealed class MyGameEntry : TryGetMonoEntry
{
    protected override void Setup(IModuleHost host)
    {
        host.Register<ITimerModule>(new TimerModule());
        // ...
    }
}
```

## 5. 风险点

| # | 风险 | 缓解 |
|---|------|------|
| 1 | INetClient/Server 契约定得太死，限制 V1.1+ KCP/TCP 实现自由度 | 仅定义"连接生命周期 + 收发消息 + 状态"的最小集；不强制连接池 / 重连 / 心跳（这些是 Adapter 内部决策） |
| 2 | Samples/Shared/ 在 Unity 端的接入方式（直接源引用 vs DLL plugin） | Iter 1 决策：默认源引用（asmdef include + 物理路径），DLL 路径留 V1.1+ Adapter 化 |
| 3 | INetMessage 是空 marker，序列化跨端不一致 | 文档化"INetMessage 必须能被 V1.1+ ISerializer 处理"+ MemoryPack 推荐路径 |
| 4 | IPlugPoint 网络 5 件套 与 V0.9 ModuleHost Before/After Update 重复设计感 | 文档说明：ModuleHost IPlugPoint 是"全局横切"，Net IPlugPoint 是"连接级横切"，作用域不同；网络 5 件套生命周期由 INetServer/Client 触发 |
| 5 | TryGetMonoEntry 提供后业务可能在 Awake 内同步阻塞调 `ConnectAsync` 拖慢启动 | 文档化"Awake 仅初始化 + Initialize，业务异步操作走 Procedure / TGTask" |
| 6 | ITickLoop 与 IClock 概念重叠（用户可能困惑） | XML doc 明确："IClock=查时间，ITickLoop=被调度"，并在 ADR-0019 加示意图 |
