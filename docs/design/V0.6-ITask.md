## 1. 设计目标

让 Core 在 dotnet console 和 Unity 端**都能**跑出如下业务代码，**完全不依赖 `System.Threading.Tasks.Task` 的 ThreadPool、不依赖 UniTask、不依赖 Unity 的 Awaitable**：

```csharp
public sealed class LoginProcedure : IAsyncProcedure
{
    public async ITask OnEnterAsync()
    {
        var logger = _host.Get<ILogger>();
        logger.Info("Login started");

        var timer = _host.Get<ITimerModule>();
        await timer.WaitAsync(0.5f);     // 模拟连服务器

        var config = _host.Get<IConfigSource>();
        var loginCfg = await config.LoadAsync<LoginConfig>("Login.bin");

        var asset = _host.Get<IAssetSource>();
        var prefab = await asset.LoadAsync<GameObject>("UI/LoginPanel");

        logger.Info("Login done");
    }
}
```

### 1.1 非目标（明确不做）

- 多线程异步（ThreadPool / ParallelFor / SemaphoreSlim 等）。`ITask` 是 **单线程模型**。
- Native AOT 100% 兼容（V0.6 不强求，V0.9 SourceGen 引入后再评估）。
- 取代标准 `System.Threading.Tasks.Task`。`ITask` 与 `Task` 共存：纯 IO、文件、网络异步用 `Task`，业务流程用 `ITask`。
- 长生命周期 actor / fiber（这是 V2+ 业务层，不是基础架构）。

## 2. 对标研究

### 2.1 ETTask（egametang/ET）

**核心选择**：
- `ETTask` 是 class（不是 struct），通过 `ETTask.Create(bool fromPool = true)` 拿到 pool 中复用的实例。
- 用 `ConfiguredETTaskAwaitable` 实现 await。
- ET9 起内部传 `Context`（上下文对象）替代显式 `CancellationToken`，调用链中 `await` 自动透传。
- `ETTaskCompleted` 静态实例作为已完成任务（避免 alloc）。

**优点**：
- 上下文自动透传，减少 CancellationToken 污染。
- Pool 复用 + 已完成单例 → GC 几乎为零。

**缺点**：
- class 实例传递 = 引用语义，复制成本低但生命周期管理更复杂（"who owns the ETTask"）。
- 上下文透传机制隐式，新人不易理解。

### 2.2 FTask（qq362946/Fantasy）

**核心选择**：
- 与 ETTask 类似的 class + Pool 设计。
- 配套 Source Generator 生成 `await` 衔接代码（如 `MessageHandlerGenerator`）。
- 与 Native AOT 充分协同。

**优点**：
- AOT 友好（编译期生成路径，运行时零反射）。
- 与 Fantasy Source Generator 全家桶天然集成。

**缺点**：
- 强依赖 Source Generator，没有 SourceGen 等于"不能用"。
- V0.6 不上 SourceGen，所以 FTask 形态不能直接抄。

### 2.3 HTask（dcze/hsenl）

**核心选择**：
- `HTask` 是 **struct**（按值传递），`StructLayout(LayoutKind.Auto)`。
- struct 内部持 `IHTaskBody _body`（class，可池化）+ `int _version`（防过期 sentinel）。
- `[AsyncMethodBuilder(typeof(AsyncHTaskMethodBuilder))]` 指定 builder 类型，让 C# 编译器把 `async HTask` 转成 builder 驱动的状态机。
- `HTaskType` 枚举（Builder / Manual）区分 "由编译器自动构建" vs "用户手动 `Create`"，禁止用户对 Builder 类型的 task 调用 `SetResult`。
- `Awaiter` 是 readonly struct + `ICriticalNotifyCompletion`。
- `_version != body.Version` 触发 `HTask's body is expired!` 异常。

**优点**：
- struct 按值传递 = 零分配（不算 body）。
- `_version` 机制干净地防止 "struct 被复制到别处后 await 已回收的 body" 这个隐式 bug。
- 无 Source Generator 依赖。
- 单线程 + Pool 设计完整。

**缺点**：
- `_version` 增加内存（int 4 byte）和判断开销。
- 实现略复杂（struct + class + builder + awaiter + completion source）。

### 2.4 V0.6 ITask 取舍 — 跟 HTask 走

**决策**：完全采用 hsenl HTask 风格（struct + class body + version 防过期 + AsyncMethodBuilder），原因：
1. **struct 形态零分配**，比 ETTask class 更省。
2. **`_version` 机制最干净**，比 ETTask 的"谁拥有 task"心智模型简单。
3. **无 Source Generator 依赖**，符合 V0.6 不引入 SourceGen 的边界。
4. **API 几乎 1:1 对应 ValueTask / UniTask**，使用方学习成本低。

**差异化（与 HTask 不同的点）**：
1. 命名：`ITask` 而非 `HTask`（保持 TryGet 命名一致性）。
2. 配 Context：参考 ETTask 的上下文透传思路（V0.6 后期 Iter，先不在 Iter 1 引入）。
3. 与 `ITimerModule` / `IAssetSource` / `IProcedureModule` 显式集成（hsenl 没这层）。
4. 命名空间：`TryGet.Async`，不与 Core 其它模块混杂。

### 3.2 `ITask` 与 `ITask<T>`

```csharp
namespace TryGet.Async
{
    [AsyncMethodBuilder(typeof(AsyncITaskMethodBuilder))]
    [StructLayout(LayoutKind.Auto)]
    public readonly partial struct ITask
    {
        internal readonly ITaskBody Body;
        internal readonly int Version;
        internal readonly ITaskType TaskType;

        public Awaiter GetAwaiter() => new Awaiter(this);

        public bool IsCompleted
        {
            get
            {
                if (Body == null) return true;
                return Body.IsCompleted;
            }
        }

        public void Forget() { /* 显式 fire-and-forget，不抛 UnobservedException */ }

        public readonly struct Awaiter : ICriticalNotifyCompletion
        {
            private readonly ITask _task;

            public Awaiter(ITask task) => _task = task;

            public bool IsCompleted => _task.Body?.IsCompleted ?? true;

            public void GetResult()
            {
                if (_task.Body == null) return;
                if (_task.Version != _task.Body.Version)
                    throw new TaskExpiredException();
                _task.Body.GetResult();
            }

            public void OnCompleted(Action continuation) => _task.Body!.OnCompleted(continuation);
            public void UnsafeOnCompleted(Action continuation) => _task.Body!.UnsafeOnCompleted(continuation);
        }
    }

    public readonly partial struct ITask<T>
    {
        internal readonly ITaskBody<T> Body;
        internal readonly int Version;
        internal readonly ITaskType TaskType;

        public Awaiter GetAwaiter() => new Awaiter(this);

        public bool IsCompleted => Body?.IsCompleted ?? true;

        public readonly struct Awaiter : ICriticalNotifyCompletion
        {
            private readonly ITask<T> _task;

            public Awaiter(ITask<T> task) => _task = task;

            public bool IsCompleted => _task.Body?.IsCompleted ?? true;

            public T GetResult()
            {
                if (_task.Body == null) return default;
                if (_task.Version != _task.Body.Version)
                    throw new TaskExpiredException();
                return _task.Body.GetResult();
            }

            public void OnCompleted(Action continuation) => _task.Body!.OnCompleted(continuation);
            public void UnsafeOnCompleted(Action continuation) => _task.Body!.UnsafeOnCompleted(continuation);
        }
    }

    internal enum ITaskType : byte
    {
        Builder = 0,   // 由 AsyncITaskMethodBuilder 创建（async 方法返回值）
        Manual = 1,    // 由 ITaskCompletionSource 创建（手动控制）
    }
}
```

### 3.3 `ITaskBody` / `ITaskBody<T>`（内部 class，pool 复用）

```csharp
namespace TryGet.Async
{
    internal interface ITaskBody
    {
        int Version { get; }
        bool IsCompleted { get; }
        void GetResult();
        void SetResult();
        void SetException(Exception ex);
        void OnCompleted(Action continuation);
        void UnsafeOnCompleted(Action continuation);
        void Reset();          // 由 Pool 调用，version++ 并清空 continuation 列表
    }

    internal interface ITaskBody<T>
    {
        int Version { get; }
        bool IsCompleted { get; }
        T GetResult();
        void SetResult(T value);
        void SetException(Exception ex);
        void OnCompleted(Action continuation);
        void UnsafeOnCompleted(Action continuation);
        void Reset();
    }
}
```

### 3.4 `ITaskCompletionSource`

```csharp
namespace TryGet.Async
{
    public sealed class ITaskCompletionSource
    {
        private ITaskBody _body;

        public ITaskCompletionSource() => _body = TaskPool.Rent();

        public ITask Task => new ITask(_body, _body.Version, ITaskType.Manual);

        public void SetResult() => _body.SetResult();
        public void SetException(Exception ex) => _body.SetException(ex);
        public void SetCanceled() => _body.SetException(new TaskCanceledException());

        // 完成后由用户调用，归还 body 给 pool；不归还也不漏（Pool 满则 GC）
        public void Return()
        {
            if (_body == null) return;
            TaskPool.Return(_body);
            _body = null;
        }
    }

    public sealed class ITaskCompletionSource<T>
    {
        // 同上结构
    }
}
```

### 3.5 `AsyncITaskMethodBuilder`

```csharp
namespace TryGet.Async
{
    public struct AsyncITaskMethodBuilder
    {
        private ITaskBody _body;

        public static AsyncITaskMethodBuilder Create() => new AsyncITaskMethodBuilder { _body = TaskPool.Rent() };

        public ITask Task => new ITask(_body, _body.Version, ITaskType.Builder);

        public void SetResult() => _body.SetResult();
        public void SetException(Exception ex) => _body.SetException(ex);

        public void Start<TStateMachine>(ref TStateMachine sm) where TStateMachine : IAsyncStateMachine
            => sm.MoveNext();

        public void SetStateMachine(IAsyncStateMachine sm) { /* no-op for struct body */ }

        public void AwaitOnCompleted<TAwaiter, TStateMachine>(ref TAwaiter awaiter, ref TStateMachine sm)
            where TAwaiter : INotifyCompletion
            where TStateMachine : IAsyncStateMachine
        {
            awaiter.OnCompleted(sm.MoveNext);
        }

        public void AwaitUnsafeOnCompleted<TAwaiter, TStateMachine>(ref TAwaiter awaiter, ref TStateMachine sm)
            where TAwaiter : ICriticalNotifyCompletion
            where TStateMachine : IAsyncStateMachine
        {
            awaiter.UnsafeOnCompleted(sm.MoveNext);
        }
    }

    public struct AsyncITaskMethodBuilder<T>
    {
        // 同上结构 + SetResult(T value)
    }
}
```

## 4. 实现策略

### 4.1 渐进式 Iter 顺序（与路线图 §1.3 一致）

| Iter | 增量 | 验收 |
|---|---|---|
| 1 | `ITask` struct + `Awaiter` + `AsyncITaskMethodBuilder` 骨架（body 临时用 new、不 pool） | `async ITask MyMethod() { return; }` 编译且运行通过 |
| 2 | `ITaskCompletionSource` + `ITaskBody` 状态机 | `var tcs = new ITaskCompletionSource(); var t = tcs.Task; tcs.SetResult();` 工作 |
| 3 | `_version` + `TaskExpiredException` | 复制 struct 后 body Reset 再 await 抛 expired |
| 4 | `TaskPool` 池化 | 100 万 await GC < 1MB |
| 5 | `ITaskScheduler.Yield/Delay/WaitForFrames` | `await scheduler.Delay(1f)` 1s 后 continuation |
| 6 | `ITimerModule.WaitAsync(): ITask` 扩展 | `await timer.WaitAsync(1f)` 工作 |
| 7 | `IAsyncProcedure` + `ProcedureModule` 异步支持 | `OnEnterAsync` 跑通 |
| 8 | 异常 + Cancel + Forget + UnobservedException 钩子 | 测试覆盖 |
| 9 | 测试 30+ | 全绿 |
| 10 | `Samples/Net/Program.cs` 雏形 | dotnet console 跑通 |
| 11 | CHANGELOG + ARCHITECTURE.md 更新 | merge |

### 4.2 关键实现细节

#### 4.2.1 状态机 continuation 列表

`ITaskBody` 内部如何存 continuation：

- **方案 A**：`Action _continuation` 单个（多 await 同一 task 时挂多个 continuation 会丢）
- **方案 B**：`List<Action> _continuations`（每次 await 都加，alloc）
- **方案 C**：链表节点（每节点是 ValueTuple 持下一节点指针，节点也走 pool）

**V0.6 选 A**：因为 `ITask` 设计上只允许"一次 await"（多次 await 同一 task = 用户错误）。Iter 8 加 `EnsureNotAwaited` 检测多次 await 抛异常。

#### 4.2.2 同步 continuation vs 异步入队

`OnCompleted` 实现：

- 如果 `IsCompleted == true`（task 已完成），continuation 立即同步执行
- 否则把 continuation 存到 `_continuation`，等 `SetResult / SetException` 时同步执行

**深递归保护**：维护线程级 `_invocationDepth`，超过 16 层时入队 `ITaskScheduler` 异步执行（Iter 5 加入）。

#### 4.2.3 `_version` 溢出处理

`int.MaxValue - 2` 为 `MaxVersion`，到达时主动 Reset Pool 让所有 body GC（用户无感）。

#### 4.2.4 Builder vs Manual 区分

- `ITask` 从 `async ITask MyMethod()` 编译生成的状态机得到 → `TaskType = Builder`
- `ITask` 从 `new ITaskCompletionSource().Task` 得到 → `TaskType = Manual`
- 调用 `ITask.SetResult()`（不是 Awaiter.GetResult）时，仅 Manual 允许，Builder 抛 `InvalidOperationException`

参考 hsenl HTask:64-67 的 `_taskType` 限制。

#### 4.2.5 与 Unity 主循环衔接

`ITaskScheduler` 实现 `IUpdateModule`，由 Unity Adapter 端的 `TryGetMonoEntry.Update()` 驱动 `host.Update(dt, udt)` 时间片。Net 端的 `Samples/Net/Program.cs` 手写主循环同样驱动。

## 6. 已知失败模式 + 缓解

| # | 失败模式 | 现象 | 缓解 |
|---|---|---|---|
| 1 | C# 编译器拒绝 `[AsyncMethodBuilder]` attribute | `error CS8400: Feature 'extended' is not available` 或类似 | Iter 1 加 spike 测试在最小项目中跑通；必要时加 `<LangVersion>9.0</LangVersion>`（已在 Shadow csproj 设置） |
| 2 | `_version` 在编译器生成的状态机中被复制错位 | 看似随机的 `TaskExpiredException` | Iter 3 加详细诊断 + 在 `Awaiter.GetResult` 抛异常时附带 stack frame 信息 |
| 3 | Pool 在多线程场景下竞态 | 罕见但灾难性的 body 复用错位 | V0.6 强制单线程；在 `TaskPool.Rent/Return` 加 `ThrowIfNotMainThread`（debug 构建） |
| 4 | `OnCompleted` 同步执行导致深递归爆栈 | StackOverflowException | Iter 5 后引入"调度深度计数器" |
| 5 | `IAsyncProcedure.OnExitAsync` 抛异常时状态机卡死 | Procedure 停在中间态 | Iter 7 加 timeout + 进入降级路径（强制 OnExit 同步 Cleanup） |
| 6 | 用户对同一 ITask 多次 await | 第二次 await 行为未定义 | Iter 8 在 `Awaiter.OnCompleted` 加 `_awaited` 标记，重复 await 抛 |
