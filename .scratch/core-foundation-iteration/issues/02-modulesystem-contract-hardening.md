# ModuleSystem Contract Hardening

## Parent

.scratch/core-foundation-iteration/PRD.md

## What to build

Harden the ModuleSystem contract end to end: service-interface registration, dependency topology, lifecycle rollback, Shutdown aggregation, FramePhase dispatch, and GameLauncher baseline registration. The goal is to lock the route C ModuleSystem behavior as a stable deep module that future UI, resource, and scene modules can depend on.

## Acceptance criteria

- [x] Registering a Module through its service interface succeeds, while registering concrete classes, framework base interfaces, and duplicate service interfaces fails with actionable errors.
- [x] DependsOn controls initialization order, Priority only breaks ties among topology-equivalent Modules, and Shutdown runs in the reverse initialized order.
- [x] Missing dependencies and circular dependencies fail before any partial host reaches IsInitialized.
- [x] Initialize failure rolls back already initialized Modules in reverse order and leaves the host uninitialized.
- [x] Shutdown continues through individual Module failures, clears frame dispatch state, and reports an aggregate failure.
- [x] EarlyUpdate, FixedUpdate, Update, LateUpdate, and EndOfFrame only dispatch after Initialize and follow initialized Module order.
- [x] GameLauncher creates a host with the Core baseline services and applies generated Module/EventHandler registrations through the runtime registries.
- [x] Tests verify the public behavior above without asserting private collection layout.
