# Timer Contract And TGTask Bridge

## Parent

.scratch/core-foundation-iteration/PRD.md

## What to build

Harden TimerModule's callback-oriented contract and its relationship to TGTask async extensions. This slice should define and verify one-shot timers, repeat timers, pause/resume, cancel semantics, scaled/unscaled time, long-frame catch-up, callback exception aggregation, and whether TimerModule async waits need cancellation parity with TGTaskScheduler.

## Acceptance criteria

- [x] One-shot timers fire once, are removed after firing, and return false when canceled after completion.
- [x] Repeat timers support pause, resume, cancel, pending count, and documented long-frame catch-up behavior.
- [x] Scaled and unscaled timers advance from their respective delta inputs.
- [x] Timer callbacks can cancel or pause their own timer without being overwritten by the current update pass.
- [x] Multiple due timer callbacks in the same update are all attempted even when one throws, and failures are reported as an aggregate after traversal.
- [x] TimerModule Shutdown clears pending timers and leaves no callback scheduled.
- [x] TimerModule async extensions either gain TGCancelToken overloads or explicitly document why TGTaskScheduler is the cancellable await-oriented delay service.
- [x] Tests cover TimerModule through ITimerModule and extension methods, not private entry storage.
